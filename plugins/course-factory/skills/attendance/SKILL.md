# Attendance (review & record)

> **Bootstrap:** if you start from zero: (1) locate the course root — the nearest ancestor folder
> containing `.claude/refs/course.yaml`; (2) read `course.yaml` — in particular
> `naming.folders.students`, `tool_stack.miro`, `evaluation.attendance` (the policy thresholds),
> and `publishing.drive`; (3) read `.claude/refs/PROTOCOL.md` — attendance is defined in §9; (4)
> for a virtual session, read that session's handover `.claude/refs/handovers/handover-S<NN>.md`
> **ONLY to get the Miro board IDs** (the "Materialización en Miro" table) — attendance does NOT
> otherwise couple to the handover/pipeline; (5) read `.claude/refs/shared-context.md`. **GATE:**
> if `attendance` is not in `artifacts.enabled`, STOP and warn the conductor; for Miro auto-review
> mode, also require `tool_stack.miro.enabled` to be `true` (manual mode does not need it).
>
> **Guard:** this skill runs **STANDALONE after a session concludes** — it is **NOT** part of the
> session production pipeline. It writes **NO** handover and emits **NO** next-agent prompt.

**Tier / work split:**

| Layer | Who | Does |
|---|---|---|
| Orchestration + judgment | **Opus (you)** | Orchestrates the whole run; JUDGES relevance and authorship flags; decides the deterministic present/absent computation; writes the ledger; reports to the instructor. |
| Matching + drafting | **Sonnet** (delegate) | Fuzzy-matches frame titles → roster entries; drafts relevance verdicts from each frame's student-created content against the exercise consigna. |
| Mechanical execution | **Haiku / Opus-via-Bash** | Runs the reader script `leer_tablero.py`; publishes the export Sheet via the Drive MCP. |

## Gate: config

This skill only runs when `attendance` is in `course.yaml artifacts.enabled`. For the Miro
auto-review mode it additionally requires `tool_stack.miro.enabled: true`; the manual-entry mode
does not need Miro at all. If the gate fails, stop immediately and tell the conductor.

## What you produce

Updates `<folders.students>/attendance-<section>.json` — **one combined JSON per section**
(roster + policy + sessions together in the same file; canonical section keys are `Ad` and `Mk`).
Optionally, a per-section **%-attendance Google Sheet** built from the exported CSV.

## The JSON ledger

```jsonc
{
  "section": { "id": "Ad", "label": "Administración" },
  "policy": { "class_present_threshold": 0.5, "max_absences": 8, "absence_alert_fraction": 0.75 },
  "miro_account_map": {},           // learned carné -> miro_user_id, from confirmed matches
  "roster": [
    { "carne": "24001301", "name": "…", "email": "…", "status": "active",
      "joined_session": "S01", "notes": "" }
  ],
  "sessions": {
    "S01": {
      "date": "2026-07-06", "type": "virtual", "mode": "miro", "exercises": ["02"],
      "boards": { "02": { "id": "uXjVH-3WFJk=", "url": "https://miro.com/app/board/uXjVH-3WFJk=" } },
      "reviewed_at": "2026-07-13",
      "records": {
        "24001301": {
          "exercises": { "02": { "located": true, "relevant": true, "authored_by_self": true,
                                 "participated": true, "frame_id": "…", "frame_title": "…",
                                 "content_authors": ["<miro id>"], "notes": "" } },
          "exercises_participated": 1, "exercises_total": 1, "participation_rate": 1.0,
          "present": true, "flags": [], "notes": ""
        }
      },
      "flags": { "new_students": [], "unmatched_frames": [], "shared_account_authors": [] }
    }
    // manual session: { "type":"workshop","mode":"manual","source":"acta con firmas …",
    //   "records": { "24001301": { "present": true, "source": "acta", "notes": "" } } }
  },
  "summary": { /* regenerated by build_attendance_sheet.py */ }
}
```

Invariants — respect these exactly:

- **present/absent is ALWAYS deterministic.** There is **no third status**. Per exercise,
  `participated = located AND relevant`. Per session, `present = participation_rate ≥
  policy.class_present_threshold`.
- **"Fishy" findings are FLAGS, never a status.** They alert the instructor for manual review and
  **never**, by themselves, flip present↔absent (the instructor may manually override a record and
  re-export). Flags live in the per-record `flags[]` and the session-level `flags` block.

## Inputs

- The session's Miro board IDs, from `.claude/refs/handovers/handover-S<NN>.md` (read ONLY for
  this — see Guard above).
- The exercise slots/consignas, from `<folders.exercises>/S<NN>-*.md`.
- The section roster + policy, from `<folders.students>/attendance-<section>.json` itself.
- For manual mode: the acta present-list supplied by the conductor.
- Environment: `MIRO_TOKEN` (never written to any file), read by `leer_tablero.py`.

## The three controls

1. **`located`** — the frame TITLE parses to a carné/name that fuzzy-matches the roster. Titles
   are messy (`24001301 - Fabricio`, `Germayoni Murillos - 24005311`, `Maria Soto-24001216`) —
   match on the **carné digits primarily**, name secondarily.
2. **`relevant`** — the frame contains **student-created** content: child items whose
   `created_by_id` ≠ the board's `service_account_id` (i.e. not the seeded scaffolding),
   representing a real attempt, not an empty/name-only frame. Sonnet drafts the verdict, Opus
   confirms.
3. **`authored_by_self` (FLAG layer only)** — from the student-created items' authorship: **flag**
   when (a) the content-author name (resolved via board members) does not match the student named
   in the title, or (b) one Miro account authored content across many different students' frames
   (see `author_frame_counts`) — the proxy/impersonation signal. IMPORTANT: the frame TITLE is
   **not** attributable to the student (the frame was created by the instructor's build script;
   renaming only touches `modifiedBy`), so authorship is judged from the **content**, and email is
   Enterprise-gated so matching is on **names**. Mismatches are flags, never auto-absent.

## Modes & Process

### (a) Review a virtual (Miro) session — default

The default mode for a prompt like "Review attendance for S01." Covers **every enabled section**
for that session (Ⓐ→`Ad`, Ⓑ→`Mk`).

1. Get each section's board id(s) from `handover-S<NN>.md`; get the exercise slots + consignas
   from `<folders.exercises>/S<NN>-*.md`.
2. For each section board, run the reader (Haiku/Bash):
   `python3 "${CLAUDE_PLUGIN_ROOT}/skills/attendance/scripts/leer_tablero.py" <board_id> --out <scratch>/S<NN>-<section>-frames.json`
   (reads `MIRO_TOKEN` from env; if unset/401 → stop, alert the conductor). Output = per-frame
   title + student-created children + author info + `service_account_id` +
   `author_frame_counts`.
3. **Match** (Sonnet): parse each frame title → carné/name, fuzzy-match to roster. An
   unmatched-but-parseable carné → auto-append to roster (`status:"active"`,
   `joined_session:"S<NN>"`) AND record in session `flags.new_students`. A title with no
   parseable carné → session `flags.unmatched_frames`.
4. **Assess** the three controls per matched student/exercise; set `located`/`relevant`/
   `authored_by_self`, `participated = located AND relevant`, store evidence (`frame_id`,
   `frame_title`, `content_authors`). Attach `flags[]` for fishy cases (`name_only`,
   `authored_by_other`, `content_by_shared_account`).
5. Roll up per student: `exercises_participated`, `participation_rate`, deterministic `present`.
6. Write `students/attendance-<section>.json`; run the export script to refresh `summary`.
7. **Report to the instructor**: new students auto-added, the flag/manual-review queue, and any
   absence-alert students (≥75% of max).

### (b) Manual session

For workshops/labs/exams with no Miro board (`--manual`): the instructor supplies an acta
present-list (carnés present, e.g. from a signed acta). Set the session `mode:"manual"`, `type`
from `course.yaml schedule.session_types`, `source` (e.g. "acta con firmas <fecha>"); set each
present carné `present:true`; every enrolled roster member NOT in the list → `present:false`. No
per-exercise controls apply.

### (c) Export

Run:
`python3 "${CLAUDE_PLUGIN_ROOT}/skills/attendance/scripts/build_attendance_sheet.py" <students>/attendance-Ad.json <students>/attendance-Mk.json`
→ refreshes each JSON's `summary`, writes `<id>-asistencia.csv` per section, prints alerts/flags.
Then delegate CSV→Google Sheet publish to Haiku via the Drive MCP `Google_Drive.create_file` with
`contentMimeType: text/csv` (the same pattern `recap-signup` uses) into the appropriate Drive
subfolder; **VERIFY** it converted to a real Sheet; record the link. One Sheet per section.

**Policy source:** read `max_absences`, `class_present_threshold`, `absence_alert_fraction` from
`course.yaml evaluation.attendance` (mirrored into each JSON's `policy` block).

## Acceptance criteria

- [ ] Every enrolled roster student has a record for the reviewed session.
- [ ] Present/absent is deterministic: `participated = located AND relevant`; `present =
      participation_rate ≥ policy.class_present_threshold`.
- [ ] Fishy cases are **flags**, never silently resolved and never a third status.
- [ ] New students are auto-appended with `joined_session` AND reported to the instructor.
- [ ] Absence alerts (≥ ceil(0.75 × max_absences)) are surfaced.
- [ ] Evidence (`frame_id` / `frame_title` / `content_authors`) is stored for every located record,
      for disputes.
- [ ] Both section JSONs remain valid JSON after the write.
- [ ] `MIRO_TOKEN` never appears written in any file.
- [ ] Any persistent API failure is escalated to the conductor.

## Close

- Write/refresh the ledger; run the export; **report to the instructor** (new students, flag
  queue, absence alerts).
- Optionally record a durable new lesson in `.claude/refs/shared-context.md` (e.g. matching
  quirks, Miro authorship calibration).
- **Explicitly:** this skill writes **no** session handover and emits **no** next-agent prompt — it
  runs standalone after the session concludes.
