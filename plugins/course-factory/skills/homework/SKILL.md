# Homework (formal take-home statement + rubric)

> **Bootstrap:** if you start from zero: (1) locate the course root — the nearest ancestor
> folder containing `.claude/refs/course.yaml`; (2) read `course.yaml` (language, folder
> names, enabled artifacts, tool stack, publishing targets); (3) read
> `.claude/refs/PROTOCOL.md` — the course's contract; (4) read your session handover
> `.claude/refs/handovers/handover-S<NN>.md` if it exists; (5) read
> `.claude/refs/shared-context.md`. If `homework` is not in `artifacts.enabled`, STOP and warn
> the conductor. Write ALL generated content in `course.language`.

**Tier:** Opus (you orchestrate and judge) · Sonnet (drafts the statement) · Haiku/Bash
(materializes the rubric by running `generate_rubric.py`).

## Why homework is a separate artifact

In-class exercises are formative (with rare exceptions the course PROTOCOL may declare) and live
alongside a slide/board artifact. Homework is different: it is done **outside** class, the
student reads it **alone**, and it **counts toward the grade** per `course.yaml
evaluation.weights`. That is why it needs its own formal document in Drive (a Google Doc) and
its own rubric.

## What you produce

In the `<folders.homework>/` folder (default `homework/`, per `course.yaml naming.folders`):

1. **`<folders.homework>/S<NN>-homework.md`** — the formal statement for the student, with the
   rubric embedded as a Markdown table at the end. This is what gets published as a Google Doc.
2. **`<folders.homework>/S<NN>-rubric.json`** — the rubric source (criteria, weights,
   descriptors).
3. **`<folders.homework>/S<NN>-rubric.xlsx`** — the rubric for grading (generated by
   `generate_rubric.py`).

## Inputs (read, don't duplicate)

- The session plan (`<folders.planning>/S<NN>-plan.md`) → its homework section (base statement,
  deliverable, AI-use declaration level per the course's AI-use policy). This is your contract:
  the plan already defined the *what*; you produce the formal statement.
- The session's reading (if the course has one) and the session's overall arc, to tie the
  homework to the content.
- `sources.glossary` and the syllabus's evaluation/submission-format section.

## Process

1. **Formal statement (Sonnet).** Draft, from the plan's homework section, a clean statement for
   the student with: **title · objective/context (1–2 sentences) · numbered instructions ·
   concrete deliverable · submission format** (per `publishing.portal`, cover page with name +
   ID, on-time submission) · the **AI-use declaration level** (per the course's AI-use policy in
   its sources/PROTOCOL, if the level requires declaring AI use). Non-technical, brief,
   self-contained.
2. **Rubric (engine `evaluation-rubrics:rubric-creator`).** Homework counts toward the grade →
   it needs an analytic rubric. **You author the JSON** and run it through the plugin's script:
   - **Criteria = the statement's steps/deliverables** (one criterion per verifiable
     step/deliverable; do not invent "holistic" criteria or collapse steps). Three descriptor
     levels:
     - **Meets (100%):** an exhaustive, specific checklist of every verifiable element of the
       step.
     - **Partially meets (60%):** substantial but incomplete; describe the gap. If the step
       states a count (e.g. "4–6 items"), use it as the threshold; if there is no count, don't
       invent one.
     - **Does not meet (0%):** covers both absent *and* attempted-but-fundamentally-incorrect;
       say concretely what's wrong. Never "poor quality."
     - Criterion names 3–6 words, formal register. *(Detail: the rubric plugin's
       `$(dirname "$RC")/../references/performance-levels.md`, resolved from the located
       `generate_rubric.py`.)*
   - **Weights MUST sum to 100** (hard assert in `generate_rubric.py`). This artifact's share of
     `course.yaml evaluation.weights` is applied separately in the gradebook — not here.
   - **Standard penalties (ALWAYS) — passed as `penalties`, NOT additive criteria.** Copy the
     rows from `.claude/refs/grading-penalties.md` into the JSON `penalties` field verbatim (do
     not reinvent them). The plugin renders them as a separate labeled block below the additive
     table, outside the 100 (so they don't break the `sum==100` assert).
   - **Materialize:** write `S<NN>-rubric.json` with schema:
     ```json
     {
       "language": "<course.language>",
       "criteria": [ {"name":"…","cumple":"…","parcial":"…","no_cumple":"…","pts": 20}, … ],
       "penalties": [
         {"name":"Good presentation","cumple":"…","parcial":"…","no_cumple":"…","penalty":"-15"},
         {"name":"Accessible submission","cumple":"…","parcial":"N/A","no_cumple":"…","penalty":"-100%"},
         {"name":"AI declared & explainable","cumple":"…","parcial":"N/A","no_cumple":"…","penalty":"-100%"}
       ]
     }
     ```
     ```bash
     RC=$(find "$HOME"/.claude*/plugins -path "*rubric-creator/scripts/generate_rubric.py" 2>/dev/null | sort -V | tail -1)
     python "$RC" S<NN>-rubric.json S<NN>-rubric.xlsx
     ```
     *(Locate the script scoped to `~/.claude*/plugins` — never `find /`. Requires `openpyxl`.
     The plugin's "Review in Chat" step does not apply here — the conductor's md-first gate IS
     the approval. Produce the files and finish.)*
   - **If the script fails** (`openpyxl` missing → `pip install openpyxl`; weights ≠ 100 → fix
     and retry; script not found), alert the conductor and leave the `.md` with both tables
     ready anyway.
3. **Embed the rubric in the statement.** At the end of `S<NN>-homework.md` put two tables: (a)
   the additive rubric (Criterion · Meets · Partially meets · Does not meet · Pts, summing to
   100) and (b) the penalties block ("scored negatively"), sourced from
   `.claude/refs/grading-penalties.md`. The student sees both in the Google Doc.
   `generate_rubric.py` writes both into the `.xlsx` in one step.
4. **Audit (judge).** Verify against the acceptance criteria before calling it done.

## When there is no homework

Some sessions may be exempt (workshops, recess weeks, or other exceptions the course PROTOCOL
declares) — check the session plan / PROTOCOL.md before running this skill; it may not apply to
the invoking session.

## Acceptance criteria

- [ ] `S<NN>-homework.md` has a formal statement (title · objective · steps · deliverable ·
      submission format · AI-use declaration level), non-technical and self-contained.
- [ ] The assignment is resistant to trivial AI completion to the degree the plan requires
      (e.g. a real interview/audio/video deliverable, not a write-up an LLM solves in a minute)
      — only when the plan calls for that.
- [ ] Rubric generated: `S<NN>-rubric.json` + `.xlsx`, criteria aligned to the statement's
      steps, weights sum to 100.
- [ ] Standard penalties block included (Good presentation · Accessible submission · AI
      declared & explainable), copied from `.claude/refs/grading-penalties.md`, as a separate
      "scored negatively" table.
- [ ] Both the additive rubric and the penalties block appear as tables at the end of the `.md`.
- [ ] AI-use declaration level is consistent with the plan.

## Publication (this skill owns its pipeline end-to-end)

After the **human validates** the `.md`:

- **Statement** `S<NN>-homework.md` → Google Doc via the `publish-google-doc` engine (into the
  homework Drive subfolder per `publishing.drive.subfolders`).
- **Rubric `.xlsx`** → uploaded to Drive alongside the statement (a file for the instructor, not
  a Google Doc). The `.json` stays as the editable source.

## Close

1. Write the 3 files and self-audit.
2. **Human gate (md-first):** the conductor validates the `.md` (statement + rubric). *(End the
   turn with a summary; do not publish until the green light.)*
3. **Publish** the statement to a Google Doc and upload the `.xlsx` to Drive (see
   §Publication).
4. **Update the handover** (check the homework box; note the AI-use declaration level and
   whether the rubric generated or is pending), **add lessons** to `shared-context.md`, **record
   decisions** in `<folders.sources>/<sources.decisions>` if any were made, and **emit the
   closing block** per `templates/next-agent-prompt.md`: a human summary, then the PROMPT FOR
   THE NEXT AGENT — the next artifact slug comes from the course PROTOCOL's artifact sequence
   for this session type (do not hardcode a specific next slug).
